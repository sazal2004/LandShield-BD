# ল্যান্ডশিল্ড বিডি (LandShield BD)
## নিবন্ধন-পূর্ব ভূমি-ঝুঁকি বিশ্লেষণ ও লেনদেন সুরক্ষা

Spring Boot 3.4 + Thymeleaf + JPA + H2/PostgreSQL + Spring Security (Java 17)।

## সমস্যা
বাংলাদেশে ভূমি লেনদেনে অতিরিক্ত বিক্রয়, দ্বৈত বিক্রয়, দলিল-নামজারির অসামঞ্জস্য ও একই জমিতে একাধিক চলমান লেনদেনের ঝুঁকি থাকে, যা সাধারণত নিবন্ধনের পরে ধরা পড়ে।

## প্রস্তাবিত সমাধান
নিবন্ধনের আগেই মালিকানা, দলিল, নামজারি ও হস্তান্তরের ইতিহাস মিলিয়ে ব্যাখ্যাসহ নিম্ন/মধ্যম/উচ্চ ঝুঁকির ফলাফল দেওয়া।

## প্রধান ফিচার
- সম্পত্তি ও মালিকানা যাচাই, দলিল ও নামজারির সামঞ্জস্য যাচাই
- হস্তান্তরযোগ্য মালিকানা ব্যালেন্স, অতিরিক্ত বিক্রয়, দ্বৈত বিক্রয় ও অপেক্ষমাণ/চলমান লেনদেন শনাক্তকরণ
- ঝুঁকির স্কোর (০–১০০), নিম্ন/মধ্যম/উচ্চ স্তর এবং সুনির্দিষ্ট কারণ
- লেনদেনের সময়রেখা; নিম্ন-ঝুঁকির ডেমো লেনদেন সম্পন্ন করলে বিক্রেতা-ক্রেতার ব্যালেন্স স্বয়ংক্রিয় হালনাগাদ (শুধু অভ্যন্তরীণ খাতা)
- কর্মকর্তা লগইন, ড্যাশবোর্ড, চিহ্নিত কেসের কারণ, "পর্যালোচিত চিহ্নিত করুন", ডেমো লেনদেন রিসেট
- আমাদের সম্পর্কে/গোপনীয়তা পেজ ও ডামি-ডেটা বিজ্ঞপ্তি

## ঝুঁকি ইঞ্জিন যেভাবে কাজ করে
ব্যালেন্স = মূল মালিকানা + সম্পন্ন আগত হস্তান্তর − সম্পন্ন বহির্গামী হস্তান্তর।
স্কোর: অবস্থানের অমিল +২০, বিক্রেতার ব্যালেন্স নেই +৬০, দলিলে অমিল +২০, নামজারিতে অমিল +২০, অতিরিক্ত বিক্রয় +৬০, দ্বৈত বিক্রয় +৬০, চলমান লেনদেন +৫০ (সর্বোচ্চ ১০০)। ৫০ বা বেশি = উচ্চ, ২০ বা বেশি = মধ্যম, নইলে নিম্ন। শুধু নিম্ন-ঝুঁকির কেস সম্পন্ন করা যায়।

## প্রযুক্তি
Java 17, Spring Boot 3.4, Spring MVC, Thymeleaf, Spring Data JPA, Spring Security, H2 (লোকাল) / PostgreSQL (Render), Maven, Docker।

## লোকালি চালানোর নিয়ম
JDK 17+ লাগবে।
```
.\mvnw.cmd spring-boot:run     # Windows
./mvnw spring-boot:run         # Linux / macOS
```
ব্রাউজারে http://localhost:8080 খুলুন। লোকাল ডেটা মেমোরিতে থাকে, প্রতিবার চালুর সময় রিসেট হয়।

## ডেমো কর্মকর্তা তথ্য
ব্যবহারকারী `officer` / পাসওয়ার্ড `Demo@123` — শুধু ডেমো, আসল নয়। `ADMIN_PASSWORD` এনভায়রনমেন্ট ভ্যারিয়েবল দিয়ে বদলানো যায়।

## ডিপ্লয় (Render)
GitHub-এ push → Render → New → Blueprint → রিপো বাছুন (`render.yaml`) → Apply। Docker ইমেজ `prod` প্রোফাইলে PostgreSQL ব্যবহার করে (`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`)।

## কৃত্রিম ডেটা বিজ্ঞপ্তি
সব রেকর্ড কাল্পনিক। কোনো প্রকৃত নাগরিক বা সরকারি তথ্য ব্যবহার করা হয়নি। ডেমো লেনদেন শুধু ল্যান্ডশিল্ডের অভ্যন্তরীণ খাতা হালনাগাদ করে; এটি আইনগত হস্তান্তর বা সরকারি নামজারি নয়।
